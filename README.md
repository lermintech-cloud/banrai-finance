# BanRai Finance — ระบบบริหารการเงินและบัญชี โรงเรียนบ้านไร่

โรงเรียนบ้านไร่ อ.ดอยเต่า จ.เชียงใหม่ สพป.เชียงใหม่ เขต 5
โค้ดเก็บใน GitHub เปิดใช้งานผ่าน Cloudflare (Worker ตัวเดียวให้บริการทั้งหน้าเว็บและ API) ข้อมูลอยู่ใน Cloudflare D1 (ไม่จำเป็นต้องใช้ R2)

**เริ่มที่นี่: `docs/INSTALL.md`** (คู่มือติดตั้งทีละขั้น)

> **สถานะ รุ่น 1.0.0-rc.1: ครบวงจรและผ่านการทดสอบในเครื่อง แต่ยังไม่เคยรันบน Cloudflare จริง**
> ทดสอบแล้วด้วยโค้ด Worker จริง + SQLite + เบราว์เซอร์จริง (ล็อกอิน บันทึกรับ-จ่ายหลายผู้ใช้ ตั้งค่า ผู้ใช้ พิมพ์เอกสาร)
> ยังไม่ได้ทดสอบ: `wrangler`, D1/R2 ของจริง, GitHub Actions, `tsc`
> ก่อนใช้กับเงินจริง โรงเรียนต้องตรวจระเบียบและแบบฟอร์มใน `docs/REGULATIONS_REGISTER.md` และผ่านเกณฑ์ใน `docs/DEPLOYMENT.md`

## ทำอะไรได้

| ส่วน | รายละเอียด |
| --- | --- |
| เข้าสู่ระบบ | บัญชีรายบุคคล รหัสผ่านเก็บเป็น hash ล็อกชั่วคราวเมื่อผิด 5 ครั้ง บังคับเปลี่ยนรหัสที่ผู้ดูแลตั้งให้ เซสชัน 12 ชั่วโมง |
| ผู้ใช้และสิทธิ์ | ผู้ดูแลเพิ่ม/ปิดบัญชี ตั้งรหัสใหม่ กำหนดบทบาท 6 แบบ สิทธิ์ตรวจที่เซิร์ฟเวอร์ทุกคำขอ |
| รับเงิน / เบิกจ่าย | ร่าง → ส่งตรวจ → ตรวจ → อนุมัติ → จ่าย แยกหน้าที่ ออกเลขเอกสาร กลับรายการพร้อมเหตุผล กันจ่ายเกินยอด กัน Post ซ้ำ |
| งบ ทะเบียนคุม ธนาคาร โครงการ | ยอดคำนวณจากทะเบียนคุมเสมอ กระทบยอดสมุดบัญชี งบโครงการเทียบจ่ายจริง |
| แดชบอร์ด | ตารางเปรียบเทียบ 3 ตาราง กราฟ 3 แบบ |
| เอกสาร | 12 แบบ พิมพ์ทีละฉบับหรือทั้งเล่มแบบเลือกรายการ (`1-2+3`) มีเลขหน้าและสารบัญ |
| ตั้งค่า | ข้อมูลโรงเรียน ผู้ลงนาม ตราครุฑ (เก็บใน D1 หรือ R2 แบบ Private ถ้าผูกไว้) แหล่งเงิน เปิด/ปิดปีงบประมาณ |
| ตรวจสอบ | บันทึกประวัติทุกการทำรายการ การเข้าสู่ระบบ และการจัดการผู้ใช้ แก้ไขไม่ได้ |

หน้าเว็บมี 2 โหมดในไฟล์เดียว (`apps/web/public/index.html`)
- **เปิดผ่าน Worker** → โหมดฐานข้อมูลกลาง ต้องเข้าสู่ระบบ ทุกคนเห็นข้อมูลชุดเดียวกัน
- **เปิดไฟล์ตรงๆ จากเครื่อง** → โหมดสาธิต ข้อมูลตัวอย่างเก็บในเบราว์เซอร์ ใช้ฝึกหรือดูหน้าตา

## ยังไม่ได้ทำ

แนบไฟล์หลักฐานรายการ (ตาราง `attachments` พร้อม แต่ยังไม่มีหน้าจอ/endpoint), งบประมาณแบบจัดสรร/โอน, สมุดรายวัน-ผังบัญชี, ปิดงวดรายเดือน,
นำเข้ารายการธนาคาร, ดูข้อมูลปีงบเก่าจากหน้าจอ, แก้ไข/ยกเลิกร่าง, แก้บทบาทของผู้ใช้เดิม, สำรองข้อมูลอัตโนมัติ, การแจ้งเตือน

## ลองทั้งระบบในเครื่อง (ไม่ต้องมีบัญชี Cloudflare ไม่ต้อง npm install)

```bash
npm test          # ฐานข้อมูล 64 + API 35 + หน้าเว็บ 88
npm run local     # เปิด http://localhost:8788 พร้อมข้อมูลตัวอย่าง รหัสผ่านแสดงในหน้าต่างคำสั่ง
```
ต้องมี Node 22 ขึ้นไป และ Python 3 ข้อมูลของ `npm run local` อยู่ในหน่วยความจำ ปิดแล้วหาย ใช้ทดลองเท่านั้น

## หลักที่ห้ามละเมิด และกลไกที่บังคับ

| หลักการ (พิมพ์เขียว 2.3) | ถูกบังคับที่ไหน |
| --- | --- |
| เงินเก็บเป็นจำนวนเต็มสตางค์ | `CHECK (typeof(...) = 'integer')`; API รับจำนวนเงินเป็นข้อความทศนิยม |
| รายการที่ Post แล้วห้ามแก้/ลบ | ทริกเกอร์ `trg_*_frozen`, `trg_*_no_delete`; ทะเบียนคุม/Audit เป็น append-only |
| แก้หลัง Post ต้องกลับรายการพร้อมเหตุผล | สถานะ `reversed` + รายการตรงข้ามในทะเบียนคุม |
| Approved ยังไม่ใช่รายจ่ายจริง | ยอดคงเหลือมาจากทะเบียนคุมเท่านั้น |
| จ่ายเกินยอดไม่ได้ | ทริกเกอร์ `trg_expense_no_overspend` |
| ผู้ทำรายการไม่อนุมัติของตนเอง | CHECK `ck_exp_sod_*`, `ck_inc_sod_post` |
| Post ซ้ำไม่ได้ | `Idempotency-Key` + UNIQUE + `ux_ledger_one_per_source` |
| ไม่แก้ข้อมูลปีที่ปิดแล้ว | ทริกเกอร์ `*_year_open` |
| ตรวจสิทธิ์ที่ Backend | Worker อ่านสิทธิ์จากฐานข้อมูลทุกคำขอ |
| ไฟล์ไม่เปิดสาธารณะ | รูปตราครุฑอ่านได้ผ่าน Worker ที่ตรวจเซสชันเท่านั้น ไม่ว่าเก็บใน D1 หรือ R2 |
| Migration เท่านั้น ห้าม Reset Production | ไฟล์ migration ไม่มี DROP/PRAGMA/BEGIN (`verify.py` ตรวจ) |
| ไม่มี Secret ใน Git | `.gitignore`; รหัสผ่านผู้ดูแลคนแรกสร้างด้วยสคริปต์ในเครื่อง เก็บเฉพาะ hash |
